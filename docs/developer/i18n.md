# Internationalization (i18n)

TeamVault follows the standard WordPress.org translation workflow so
translators can collaborate in GlotPress instead of editing PHP.

## How it works

- All user-facing strings use the `mikesoft-teamvault` text domain
  (`__()`, `esc_html__()`, `esc_attr__()`, `esc_html_e()` …).
- There is no `load_plugin_textdomain()` call: the plugin is hosted on
  WordPress.org and requires WordPress 6.0, so WordPress auto-loads the
  GlotPress language packs from `WP_LANG_DIR` (WordPress 4.6+ behavior);
  see
  [How to internationalize your plugin](https://developer.wordpress.org/plugins/internationalization/how-to-internationalize-your-plugin/#plugins-on-wordpress-org).
- `languages/mikesoft-teamvault.pot` is the translatable-string template,
  generated with WP-CLI and shipped for GlotPress import.
- The hardcoded it/fr/es/de maps in `includes/class-mstv-i18n.php` stay as a
  **runtime fallback** (via the `gettext` filter) so the bundled interface
  languages keep working when no language pack is installed. They are not the
  translation source of truth — GlotPress is.
- Precedence: an installed language pack always wins over the bundled map, so
  the "Interface language" setting selects the fallback only and cannot
  override a locale that ships a pack. This is deliberate (GlotPress
  translations are reviewed by locale editors) and covered by
  `tests/PDMI18nRuntimeTest.php`. Forcing a different locale on sites that do
  have a pack would need a `plugin_locale` filter, which is not implemented.

## Regenerating the POT

```sh
wp i18n make-pot . languages/mikesoft-teamvault.pot --domain=mikesoft-teamvault
```

The command runs in the plugin directory without a WordPress installation.
The committed POT is the raw WP-CLI output: plugin header metadata,
`#: file:line` references, `#. translators:` comments, and `#, php-format`
flags for strings with placeholders. Regenerate it whenever user-facing
strings change, and before a release, so translators see the current set with
correct references.

## GlotPress handoff

1. Release the plugin. WordPress.org extracts the strings from the released
   plugin, so the
   [plugin GlotPress project](https://translate.wordpress.org/projects/wp-plugins/mikesoft-teamvault/)
   updates on its own; import the committed `.pot` manually only when a
   refresh is needed.
2. Approved translations ship automatically as WordPress.org language packs
   into `wp-content/languages/plugins/` — no bundled `.po`/`.mo` files
   needed.
3. Keep the fallback maps in sync until GlotPress coverage for a locale is
   complete; the maps must always cover every `mikesoft-teamvault` string
   (guarded by `tests/PdmI18nCoverageTest.php`, and the pack-over-map
   precedence by `tests/PDMI18nRuntimeTest.php`).

## Terminology

Decisions to keep the bundled locales internally consistent:

- "Vault" names the TeamVault workspace. Italian, Spanish, and German keep the
  English word; French uses "coffre". Do not mix the two forms inside one
  locale.
- Italian renders "storage" as "archiviazione" everywhere, including labels
  such as "Directory di archiviazione" and "Reindicizza archiviazione".
- Italian uses "elenco" (not "lista") and "Gestione file" for the File Manager
  screen.
- Event labels follow the WordPress Italian convention: "upload" is
  "caricamento", "download" stays "download".
